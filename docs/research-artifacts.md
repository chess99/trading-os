# 研究文件与模型交付

本规范约束公司研究的文件归档与复算方式。研究判断、价值定义、普通股归属和验收要求沿用[统一深研提示词](../prompts/company/standard-deep-research.md)及[核验附录](../prompts/company/research-verification.md)。

## 进入 Git 的内容

| 内容 | 保留范围 |
|---|---|
| 正式报告与共享状态 | 完整周期报告；由现有协调入口写入的研究字段与队列 |
| 模型与必要输入 | 可阅读、可修改的计算代码；复算所需的公司事实、假设、单位、日期及来源位置 |
| 简明结果 | 当前采用的价值区间、五年分配与终值、关键现金/权益桥、重要情景及限制；可由模型重新生成 |
| 测试 | 验证当前计算链、可手算特例、现金/权益勾稽及关键错误的少量回归用例 |

公司附件放在 `research/companies/{市场}/{代码}/models/`，按财报周期命名。优先复用可读的公共计算函数，避免为单文件交付复制或编码整套工作目录。模型运行说明写清入口、输入及结果含义；当前源码树和声明的运行依赖应足以完成常规复算。

当前周期的简明结果使用 `YYYY-Q3-output.json` 等周期文件名，包含 `symbol`、`report_period`、`value_range`、`return_model` 及必要说明，与报告和共享状态一致；对应的 `YYYY-Q3.py` 实际计算采用结果。仅保存旧值的快照不构成可复算模型。

## 留在工作目录的内容

下载的 PDF、网页与抽取缓存、候选稿、派发或返工记录、运行日志、历史失败输出、临时快照，以及可再生的长尾逐年逐节点轨迹和全量参数遍历，保存在忽略的 `tmp/`、公司 `.work/` 或 `.tmp_research/` 中。确有长期保存用途时另行归档；公开来源在报告中保留链接、日期和关键表页。外部档案不得成为常规复算、测试或网页构建的必需依赖。

禁止把工作档案以 ZIP、压缩流、Base64/Base85 字符串、二进制分片或嵌套源码常量塞入模型文件。结果只保留对当前判断有用的字段；完整轨迹可由可选参数写到临时目录，不默认写进仓库。公开 API 字段需要的计算精度保留，正文数字采用证据支持的精度。

## 大小与检查

- 新增或更新的报告、公司模型代码、输入及结果，单文件不超过 **1 MiB**。
- 同一公司、同一财报周期的模型附件合计不超过 **2 MiB**。不得用拆分、编码、压缩或改后缀规避预算。
- 超限先删除重复和可再生过程材料，检查输入与代码职责；必要的大型外部资料通过来源或独立档案引用，不自动扩张交付格式。
- 全市场状态、队列及池文件按其现有合同维护，不套用单公司体积预算。
- 常规测试和构建可在浅克隆或源码 ZIP 中运行，不读取特定历史 Git 对象、私有云目录或归档包。历史全量重演属于显式选择的维护工作。

提交前检查暂存文件的用途、大小和可复算性，运行存储检查：

```bash
python scripts/check-research-artifacts.py
```

该检查只识别存储与文件形态问题，不认证商业判断或模型正确性。继续运行现有状态校验及与变更有关的模型/工程检查，并说明实际执行范围；模型、数据核验不依赖网页浏览器验收，网页或基础设施发生实际改动时再执行相应检查。

## 清理与修订

纯文件整理保留已采用输入、数学公式、普通股口径、估值、五年分配及终值。必要输入不能与过程材料一并删去；通过当前入口重新生成简明结果并核对报告和结构化字段。发现旧模型无法复算、独立核验失败或假设错误时，明确记录缺口，按现有完整研究与验收流程修订；不得用摘要冒充可复算模型或把旧失败改写成已通过。

无法可靠估值或建模的结果允许为 `null`，保留具体原因、影响量级和后续所需事实；空值不表示价值为零。旧材料的迁出范围、原存储位置及尚未执行的验证在清理说明中简要交代，不另建证据账本、审批角色或逐文件发布登记。

本规范适用于新交付及本次明确授权的清理。既有合格报告按原周期和截止阅读；修改报告结论须完成对应研究验收。清理 Git 历史须另行保全原版本并核对范围，普通文件整理不自动授权重写历史。
