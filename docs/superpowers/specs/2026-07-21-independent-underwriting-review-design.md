# 独立承保复核与模型组合决策系统设计

日期：2026-07-21

## 目标

为 Trading OS 建立一套不能直接继承初始研究结论的二次投资审查机制，用于两类场景：

1. 从特定行业或主题的数十家公司中逐家深度复核并择优；
2. 从全 A 股覆盖层逐级筛出数十家公司，完成独立复核后给出最终模型组合建议。

系统要回答的不只是“公司好不好”，而是：

- 初始报告中的购买理由是否经一手证据复核成立；
- 最新价格对应的预期是否合理；
- 正常化利润、合理价值和买入区间能否复算；
- 在同业和全组合机会中，该公司是否仍值得配置；
- 如果可以买，当前能否买、买多少、什么情况下加仓或退出。

旧报告保持不可变。每次复核都新增报告和封存产物，保留观点被确认、削弱或推翻的完整轨迹。

## 已确认的设计决策

- 采用半盲审：复核 agent 先看到脱敏的待验证主张，但看不到旧评级、合理价、买入区和仓位；独立估值封存后才揭示旧结论。
- 采用两级决策：单公司复核只能决定是否通过承保，只有组合综合层可以决定最终买入名单和仓位。
- 默认输出标准模型组合；用户提供真实持仓后，可以再叠加个性化约束。
- 默认投资期限为 1—3 年；强周期公司额外列出未来 6—12 个月催化剂和周期反转风险。
- 默认采用一名独立复核 agent；出现重大分歧或高风险时，升级为第二名完全盲审 agent 和独立仲裁。
- 不要求向后兼容。现有结构如果妨碍正确决策，直接重构并执行一次性迁移。

## 核心原则

### 研究和投资决策分层

```text
Coverage 初筛
    ↓
Initial Research 初始深研
    ↓
Independent Underwriting Review 独立承保复核
    ↓
Portfolio Synthesis 组合决策
```

- Coverage 只决定研究资源投向。
- Initial Research 可以形成初步投资主张和估值。
- Underwriting Review 从零核验证据、重建盈利和估值，只输出承保状态。
- Portfolio Synthesis 完成同业择优、因子去重、风险预算和最终操作建议。

“单独看值得买”和“在当前组合中应该买”是两个不同问题，不能共用一个评级字段。

### 硬门槛先于评分

评分只用于通过承保后的横向排序，不能抵消来源缺失、会计风险、估值不可复算等致命问题。

### 允许现金

模型组合不以满仓或固定持仓数为目标。没有足够合格且价格合理的机会时，现金是合法结果。

各目录职责：

- `coverage/` 保存市场覆盖、筛选快照和进入研究前的候选队列；

- `research/batches/` 保存跨公司的不可变综合结果；
- `policies/` 保存带版本的承保、估值、行业和组合政策；
- `automation/runs/` 只保存可恢复的运行状态，不是投资结论来源。

### 公司元数据

新版 `meta.json` 只保存公司研究事实和状态：

- 公司身份和证券信息；
- 研究覆盖状态；
- 最近报告、各类型最近报告及完整报告历史；
- 报告和封存产物哈希；
- 最新承保状态、证据截止时间和有效性；
- 估值快照、置信度和证伪条件；
- 定期、事件和价格复核触发器。

以下内容从公司元数据中删除：

- 最终组合评级；
- 目标仓位和分批建仓计划；
- 把公司研究结论伪装成实际买卖指令的字段。

最终操作和仓位只存在于批次的 `portfolio.json` 中。

## 半盲承保流程

### 阶段一：生成待验证主张包

系统从初始报告的结构化主张中保留：

- 事实主张；
- 业务和行业假设；
- 投资逻辑；
- 需要验证的指标；
- 证伪条件；
- 原始来源清单。

系统必须删除：

- 旧评级和操作建议；
- 旧合理价值、目标价和买入区；
- 旧仓位计划；
- 能明显泄露上述结论的措辞。

新格式报告中的主张包由程序确定性生成。旧格式报告通过一次性抽取和独立泄露检查迁移；不能可靠转换的公司标为 `requires_rebaseline`。

### 阶段二：盲态重建

每家公司分配一个独立 agent。该 agent 只能接收脱敏主张包、公司身份、承保政策和允许的一手来源清单，必须重新完成：

- 关键事实核验；
- 盈利质量桥；
- 现金流桥；
- 正常化盈利桥；
- 悲观、基准和乐观三情景估值；
- 市场隐含预期反推；
- 买入区和安全边际；
- 至少三条主动寻找的反方证据。

结果写入 `blind_assessment.json`，随后计算 SHA-256、记录事件并封存。

### 阶段三：揭示和差异审计

只有封存验证通过后，系统才能揭示旧评级、旧合理价和旧仓位。复核 agent 对旧报告的每项主张标记：

```text
confirmed
weakened
disproven
untested
```

最终 `underwriting_review` 必须解释新旧差异来自：

- 新事实或新财报；
- 统计或会计口径；
- 周期位置判断；
- 估值参数；
- 旧报告事实错误；
- 无法验证的假设。

报告中的盲态结论必须与封存内容一致，不能在看到旧答案后回改独立估值。

### 阶段四：挑战和仲裁

出现升级条件时，第二名 agent 完全盲审：既不看旧报告，也不看第一名 agent 的结论。第二份结果封存后，仲裁 agent 才能同时查看两份结果和旧报告。

仲裁可以输出：

```text
passed
failed
insufficient_evidence
stale
```

没有可靠共识时默认不通过，不通过协商制造表面一致。

## 证据标准

### 证据账本

每个重要事实和判断都必须保存：

```text
claim_id
claim
value
period
original_basis
adjusted_basis
source_tier
source_uri_or_path
source_locator
retrieved_at
cross_checked
review_result
```

来源分级：

- S1：交易所公告、法定财报、监管文件和公司正式公告；
- S2：政府、行业协会、海关和招投标等权威行业数据；
- S3：可靠行情商、券商报告和专业数据库；
- S4：媒体、访谈、社交平台和市场传闻。

关键财务数字必须由 S1 支持。S3 可以提高效率，不能替代 S1。S4 只能形成线索，不能单独支持承保通过。

### 数据新鲜度

- 股价：最近一个已完成交易日；盘中报告记录精确时间；
- 财务：最新已披露定期报告，且原则上覆盖至少五个完整年度；
- 当年信息：纳入全部已披露季报、业绩预告和重大公告；
- 股本：处理分红送转、增发、回购、可转债和限售股变化；
- 强周期价格和库存：原则上不超过 30 日；
- 一般行业经营数据：原则上不超过 90 日。

超过有效期的结论转为 `stale`，不得执行新增买入。

### 三张强制桥

盈利质量桥：

```text
归母净利润
→ 扣除非经常性损益
→ 调整处置、补助、公允价值和异常减值
→ 调整资本化和会计政策变化
→ 可持续净利润
```

现金流桥：

```text
可持续净利润
→ 折旧摊销
→ 真实营运资本占用
→ 维持性资本开支
→ 股权激励和稀释
→ 所有者现金收益
```

估值桥：

```text
当前经营状态
→ 周期正常化收入和利润率
→ 悲观、基准和乐观情景
→ 企业价值或权益价值
→ 净债务、少数股东权益和潜在稀释
→ 每股合理价值区间
```

禁止把单季利润直接乘四，禁止以周期顶部利润乘一个低倍数得出“便宜”。

## 行业适配

统一证据和流程闸门之上加载行业政策：

- 强周期：产能、库存、价格曲线、成本曲线和中周期利润；
- 制造业：产能利用率、订单质量、应收、存货和资本开支；
- 软件与平台：留存、获客成本、递延收入、股权激励和现金转换；
- 银行：资产质量、拨备、息差、资本充足率和内生资本；
- 保险：新业务价值、投资收益、偿付能力和假设敏感性；
- 地产：项目货值、预售回款、净负债和表外义务；
- 资源公司：储量、品位、现金成本、维持性资本开支和商品价格情景。

没有匹配的行业适配器时可以完成证据审计，但不能自动通过承保。

## 估值和安全边际

每家公司必须：

- 使用至少两种相互独立的估值方法；不适用时明确说明；
- 给出悲观、基准和乐观情景；
- 展示关键参数敏感性；
- 从当前价格反推市场隐含假设；
- 使用正常化盈利而不是短期峰值；
- 给出可复算公式、单位、股本和净债务口径。

默认要求年化回报率：

```text
max(12%，中国 10 年期国债收益率 + 8%，公司估算权益资本成本)
```

最低安全边际：

- 高置信度：20%；
- 中等置信度：30%；
- 低置信度：不得进入模型组合；
- 强周期、治理存疑或利润波动大：原则上 35%。

安全边际是进入组合比较的必要条件，不代表满足后必然买入。

## 自动阻断和升级

### 自动阻断

任一条件成立，单公司不得通过：

- 最新法定财报或关键公告无法取得；
- 股价、股本、币种或复权口径无法确认；
- 核心购买理由只能由二手或传闻支持；
- 直接年化单季利润或直接使用周期峰值利润；
- 未处理非经常性收益、少数股东权益、净债务或潜在稀释；
- 利润和现金流严重背离而未解释；
- 存货、应收、预付款或借款异常增长而未穿透；
- 审计意见、持续经营、重大诉讼或关联交易风险未处理；
- 合理价无法从报告数据复算；
- 关键假设高度敏感却只给单点目标价；
- 数据过期；
- 没有主动寻找至少三条反方证据。

### 第二复核触发条件

- 新旧合理价值中枢相差超过 30%；
- 新复核推翻旧报告核心购买理由；
- 会计质量、治理或关联交易存在重大疑点；
- 强周期公司的周期位置无法可靠判断；
- 两种估值方法相差超过 40%；
- 悲观情景存在明显永久性损失风险；
- 公司可能进入模型组合前五大仓位；
- 综合 agent 对证据链提出实质异议。

## 单公司状态和组合操作

### 单公司承保状态

```text
passed
failed
insufficient_evidence
needs_challenger
stale
```

单公司 `passed` 只表示可以进入横向比较，不表示最终买入。

### 模型组合操作

```text
buy_now
buy_on_weakness
hold
reduce
exit
watch
reject
```

`buy_now` 必须同时满足：

```text
承保通过
AND 数据有效
AND 当前价进入买入区
AND 横向比较进入优选名单
AND 组合风险预算允许
```

## 价格输出

每家公司至少输出：

- 最新价格、时间、币种和复权口径；
- 悲观价值；
- 基准合理价值区间；
- 满足回报门槛的买入区；
- 减持或退出观察区；
- 相对合理价值中枢的折溢价；
- 基准情景预期年化回报；
- 悲观情景潜在损失；
- 上涨空间与下行风险比；
- 最可能使合理价失效的关键假设。

合理价值必须是区间，买入区必须由要求回报和安全边际反推。

## 横向比较和经济风险簇

通过硬门槛后，按以下维度排序：

- 正常化预期回报；
- 悲观情景永久损失风险；
- 证据质量；
- 商业模式和竞争优势持续性；
- 资产负债表韧性；
- 盈利和现金流质量；
- 未来 6—12 个月催化剂；
- 市场隐含预期；
- 流动性、治理和尾部风险。

除行业分类外，系统必须标记经济风险簇，例如存储价格、AI 资本开支、铜价、地产信用、出口美元周期、消费复苏和利率因子。

综合报告必须解释：

- 同一投资逻辑下最优公司是谁；
- 第二名相对第一名是否有不可替代性；
- 同时持有是否真正分散风险；
- 哪些公司只有高弹性，却没有更好的质量和赔率；
- 哪些承保通过的公司仍被更优同行挤出组合。

## 默认模型组合政策

- 单一公司目标仓位上限：5%；
- 首次建仓：目标仓位的三分之一；
- 单一行业上限：20%；
- 单一经济风险簇上限：25%；
- 前五大持仓合计上限：25%；
- 中等证据置信度公司上限：3%；
- 低置信度、治理高风险或承保未决公司：0%；
- 通常持有 12—25 家，但合格机会不足时允许少于 12 家；
- 允许保留现金。

建议仓位：

```text
min(
  单公司上限,
  行业和经济风险簇剩余额度,
  单笔允许损失 ÷ 悲观情景跌幅,
  证据置信度上限
)
```

### 分批建仓

- 第一档：进入买入区，建立目标仓位的三分之一；
- 第二档：安全边际扩大且基本面未恶化，再加三分之一；
- 第三档：新证据继续确认或价格进入深度价值区，完成目标仓位。

价格下跌如果由投资逻辑破坏导致，不得机械补仓。

## 结论失效机制

以下事件自动把承保或组合结论置为 `stale`：

- 新定期报告、业绩预告或重大经营公告；
- 股价相对复核价变化超过 10%；
- 强周期核心商品价格变化超过 10%；
- 增发、可转债、重大收购、减值或监管调查；
- 关键管理层、审计机构或控制权变化；
- 报告定义的证伪条件触发。

`stale` 可以保留历史持仓记录，但不能继续执行新增买入。

## 批次综合输出

每个批次必须给出：

| 公司 | 最新价及时间 | 悲观价值 | 合理价值 | 买入区 | 承保状态 | 最终操作 | 目标仓位 | 核心理由 |
|---|---:|---:|---:|---:|---|---|---:|---|

并分为：

- 现在可以买；
- 公司合格但等待价格；
- 需要补证据或第二复核；
- 明确不能买。

所有落选公司写入 `exclusions.jsonl` 并记录结构化理由，避免幸存者偏差和重复研究。

## 批次状态机

```text
created
→ candidates_frozen
→ packets_ready
→ blind_reviewing
→ blind_sealed
→ revealing
→ challenging（按需）
→ company_reviews_complete
→ synthesizing
→ completed
```

失败状态：

```text
blocked_missing_evidence
failed_agent
failed_validation
stale_quotes
cancelled
```

候选集合冻结后不得静默修改。新增公司必须建立新批次或明确修订批次。

## 命令行接口

```bash
python -m trading_os review create ...
python -m trading_os review prepare <run-id>
python -m trading_os review dispatch <run-id>
python -m trading_os review status <run-id>
python -m trading_os review resume <run-id>
python -m trading_os review validate <run-id> --strict
python -m trading_os review synthesize <run-id> --quotes <snapshot>
python -m trading_os review report <run-id>
python -m trading_os review run <run-id>
```

资产格式检查统一为：

```bash
python -m trading_os assets validate
```

删除容易被误认为投资审计的旧 `company audit` 命令。

`review run` 只是顺序执行各阶段，不能绕过脱敏、封存、验证、挑战或组合闸门。

## 两类入口

行业或主题批次：

```text
冻结指定候选
→ 为研究不足的公司补初研
→ 全部候选执行独立承保
→ 行业内择优
→ 放入全组合比较
```

全 A 股批次：

```text
5000 多家公司覆盖层
→ 低成本规则和量化初筛
→ 数百家公司证据筛查
→ 数十家公司初始深研
→ 少数公司独立承保
→ 最终模型组合
```

两种入口只在候选来源和前置筛选成本上不同，承保标准完全相同。

## 并行、安全和恢复

- 一家公司一个 agent；公司之间并行，公司内阶段串行；
- 状态更新采用原子写入；
- agent 领取带超时租约，失败后任务可安全重领；
- 报告验证通过前不得更新公司元数据；
- 每次状态转换写入只追加事件日志；
- 同一任务重复执行不得产生重复报告或覆盖封存内容；
- 综合阶段仅在全部公司进入终态或被结构化排除后开始；
- 价格快照作为不可变输入保存；
- 单家公司失败不破坏其他公司的结果；
- 批次支持断点续跑。

## 验证体系

### 资产验证

- 路径、Schema 和引用完整；
- 报告历史有序且不可覆盖；
- 文件哈希与清单一致；
- 公司元数据不包含组合决策字段。

### 半盲流程验证

- 主张包不含旧评级、合理价、买入区或仓位；
- 未封存不能揭示；
- 封存文件不能修改；
- 挑战 agent 不得收到旧结论或第一份结论；
- 最终报告的盲态结果与封存结果一致。

### 投资质量验证

- 一手来源覆盖率；
- 数据新鲜度；
- 三张财务桥；
- 正常化盈利可复算；
- 三情景估值和敏感性；
- 反方证据；
- 自动阻断和挑战条件。

### 组合验证

- 只有承保通过且未过期的公司可以进入组合；
- `buy_now` 的价格必须进入买入区；
- 单股、行业、经济风险簇和前五大仓位不得超限；
- 每个买入和落选决定都有理由；
- 组合权重和现金合计一致。

## 测试策略

至少覆盖：

- 报告、元数据、政策和批次 Schema；
- 所有合法和非法状态转换；
- 脱敏泄露检测；
- 封存文件篡改检测；
- 数据过期；
- 单季利润年化和峰值利润拦截；
- 合理价值复算；
- 仓位和经济风险簇约束；
- agent 失败、重复执行和断点恢复；
- 从候选冻结到模型组合的端到端流程；
- 以本次七家公司作为冲突回归样本，验证系统能够封存、升级、仲裁并留下审计轨迹。

## 一次性迁移

1. 冻结旧系统写入；
2. 保留全部历史 Markdown 报告；
3. 将能可靠解析的公司资产迁移到新 Schema；
4. 对旧报告提取结构化主张并执行脱敏泄露检查；
5. 无法可靠迁移的公司标为 `requires_rebaseline`；
6. 重建研究索引、复核计划和价格提醒；
7. 全仓严格验证；
8. 删除旧验证逻辑、旧队列入口和兼容代码；
9. 新系统成为唯一写入入口。

迁移不得修改历史报告内容，也不得为满足 Schema 编造缺失事实。

## 非目标

- 不自动连接券商或实际下单；
- 不保证投资收益；
- 不用单一量化分数替代投资判断；
- 不因全市场规模降低最终承保深度；
- 不为保留旧接口而维持错误的数据模型；
- 不把媒体热度、技术走势或股价下跌本身当成购买理由。

## 完成标准

1. 公司研究状态和组合买卖决策在数据模型上完全分离；
2. 半盲审由脱敏、封存、哈希和状态机强制，而不只依赖提示词；
3. 每家公司由独立 agent 重建证据、正常化盈利和估值；
4. 关键事实有一手来源，合理价和买入区可以复算；
5. 自动阻断和挑战条件不可绕过；
6. 行业批次和全市场批次共用同一承保核心；
7. 最终报告同时包含赢家、等待名单和所有落选理由；
8. 模型组合满足单股、行业、风险簇和证据置信度约束；
9. 运行支持并行、失败隔离、幂等重试和断点恢复；
10. 一次性迁移后不保留旧运行接口或双轨兼容逻辑。
