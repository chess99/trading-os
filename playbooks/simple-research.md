# 简化研究流程

## 目标

系统先完成一次全市场基线，此后只处理新增公司和足以影响研究的新事实。初筛负责选择研究对象；单公司研究负责形成完整、自足的当前报告。证券价格不是研究事实，不触发复核或任务。

核心原则：

1. 主 Agent 批量判断公司是否值得进行一次正式研究。
2. 所有候选使用同一份 `prompts/company/standard-deep-research.md` 及其核验附录，一家公司由一个 Agent 端到端完成。
3. 正式报告是某个信息截止时点的完整研究快照，必须脱离历史报告独立可读。
4. 估值、正常化经营、持有人回报模型输入、核心逻辑、风险排序或正式结论变化，必须生成新的完整报告。
5. 研究由公司、财务、治理、资本结构和行业经营变量驱动，不由股票价格驱动。

## 三类状态

证券范围使用 `active / inactive`；公司研究状态使用：

- `unseen`：尚未完成首次初筛；
- `ignore`：当前不值得正式研究，或正式研究后不值得持续覆盖；
- `candidate`：已被选中，等待或正在正式研究；
- `covered`：已有当前有效正式报告，值得持续维护；
- `stale`：重大新事实已使当前报告失效，等待完整更新。

活动任务只使用 `queued / running`。同一公司最多一个活动任务，任务只绑定 `candidate / stale`。只有 active `covered` 进入 `research/watchlist.jsonl`。

## 一次性全市场基线

详细判断方法见[研究队列初筛](../prompts/screening/research-triage.md)。初筛、独立质量池、产业知识与长期精选各有边界，不互相替代。

主 Agent 分批浏览 active unseen 公司的压缩事实，每家公司只做：

- `ignore`：当前不值得占用完整研究资源；
- `research_now`：商业质量、错价可能性、变化程度或关键问题的信息价值值得正式研究。

`research_now` 写入 `candidate` 并创建唯一任务。初筛不估值、不设置目标价或买点，也不生成公司 Markdown。不得按数量目标填队列，不得用单一财务指标机械决定。

## 单公司完整研究

研究者与协调器均完整阅读[统一深研提示词](../prompts/company/standard-deep-research.md)和[核验附录](../prompts/company/research-verification.md)。当前价值、未来终值与投资者愿付价格的唯一解释源是主提示词的[价值定义](../prompts/company/standard-deep-research.md#价值定义)，本流程不另定义一套区间。

同一研究者连续完成三个动作，不新增调度阶段或角色：先调查决定性问题并形成长期商业判断，再用财务、资本和普通股模型检验，最后编辑成结论先行的完整文章。编辑应删冗余、补判断；发现逻辑矛盾就回到模型修正，不能以润色代替研究。

结果只有 `covered / ignore`。worker 先只返回结构化候选；协调器完成商业判断、事实和模型核验及表达验收后，才通过 `research complete` 向以下目录原子追加正式报告：

```text
research/companies/CN/{ticker}/reports/YYYY-MM-DD.md
research/companies/CN/{ticker}/reports/YYYY-MM-DD-02.md
```

报告覆盖商业模式、竞争、行业、财务质量、普通股归属、治理、资本配置、价格评价、估值、持有人模型、风险、结论和来源，不要求各项独立成章。正文遵守主提示词的最低结构，不固定 16 章。不得写“详见前序报告”“历史分析继续有效”“沿时间线回看”来跳过正文。

候选结果未通过验收时直接丢弃并重新排队：不写报告文件，不推进 `report_path`，不占用同日 `-02/-03` 序号。只有通过验收的报告才进入不可变正式时间线。若历史中发现能够确认从未完成验收的误入稿，按数据修复删除该稿及其补写的质量审计日志，恢复前一份合格报告和原始研究任务；这不构成删除合格历史报告。

每次新正式研究必须提交非空 `return_model_note`。能可靠构造时同时提交 `return_model`，否则为 `null` 并解释实质缺口；`value_range` 无法可靠形成时同样以 `null` 和 `valuation_note` 说明。未来尚未兑现或未被承诺，不单独构成留空理由。

V1 合同不变，详细规则以核验附录为准：`schema_version: 1`、`method: annual_common_equity_irr_v1`、`currency: CNY`、`model_as_of` 与 `information_cutoff` 一致；五项年度普通股每股实际现金分配，第五年末终值必填，第三年末终值可选且独立研究。公开市场回购不列现金分配，回购和融资在现金与完全稀释股数中同步体现；已分配现金不在终值重复保留。

正文只冻结模型输入及关键说明，不固化随现价变化的 IRR。五年是接口而非竞争优势截止；不同行业可用不同经营预测和终值方法。模型不使用概率权重，不产生仓位、交易建议、收益率阈值、价格触发或 armed/hit/rearm 状态。

定期财报默认需要新的完整报告。公告或其他事实即使不改变商业逻辑，只要改变正常化利润、估值参数、`value_range`、`return_model` 输入、风险排序或 `covered / ignore`，也必须生成完整新报告，不能只写 update。

### 事实与模型验收

财报更新不是“新财报摘录＋旧报告正文”。协调器按核验附录检查整份报告，至少确认：

- 累计、报告期单季、上年同期单季和上一季度口径清楚；
- 关键旧假设与本期事实完成简洁比较，区分偏差原因、判断变化和估值影响；
- 全文一套信息截止、一处“一句话结论”标题及一致的最终判断；
- 关键原始数字、普通股归属、股本、报告时点价格和估值假设重新核验；
- 年度分配、未来终值、现金/权益桥、完全稀释股数逐项核对，正文与结构化模型一致，当前价值未被复制为未来终值；
- 两种估值方法可复算且指定主次，中枢差异超过 25% 时解释原因；
- 核心价值与不同经济情景及投资决策安全边际分开，正文核心区间与 `value_range` 一致。

PDF 抽取文本和财务勾稽可作为底稿，不未经整理直接进入报告。机械校验继续检查必需标题、结构化模型、退役价格线、已知拼接模板、截止冲突及核心价值一致性；它不解析正文回报模型数字，也不认证商业判断。正文模型与结构化字段由协调器核对，不一致则拒绝写入。

### 商业判断与表达验收

在现有验收中执行以下语义检查，不新增复核 Agent、评分、证据账本或审批阶段：

1. 找出决定性商业问题，抽查关键原表、条款及上下文：是否支持推断、符合截止、混淆公司自述和独立证据。金额核表头单位、币种、符号及列序；可勾稽关系回到原表复算，不只核对同一候选输入生成的模型。
2. 检查“长期竞争机制 → 经营表现 → 必要资本 → 普通股现金”最薄弱的一环。区分产品结构和同款提价、毛利率和毛利额、成熟业务回报和预测项目回报；风险不能只写在末尾而在基准中无依据地消失。
3. 检查最强相反解释和可比对象，以及研究者为何仍采纳当前路径。是否将同行整体数据冒充对应业务、以行业标签代替机制；正面和负面假设都要有依据。未发现可靠错价不妨碍形成质量与价格评价，主张超额回报优势时才要求具体非共识论证。
4. 检查最重要的前瞻判断进入了哪些变量：成长持续期、单位利润、资本回报、现金归属或终值等。区分现金延迟与永久损伤，五年接口不机械截断竞争优势。对支配结果的假设给出依据、范围和有意义的替代路径；两法取低、计算正确或主观加一笔溢价均不能代替商业论证。
5. 检查未知的量级及估计可用性。可合理估计的未来事项不必先获公告承诺；局部股比、合同权重或资产缺精度，不自动否定全公司估值。无法约束决定性经营路径或普通股归属时可以留空，不用详细预测掩盖缺口。禁止续贷、集中提前偿债等压力设定失败不等于基准必然不可行。历史差异区分新事实、漏用旧信息和方法/假设改变。
6. 删掉估值表后，读者是否仍能理解长期拥有或不拥有的理由？研究者是否明确作了取舍？重要限定是否改变参数、情景或改判条件？检查结论与正文、模型是否一致，删除重复免责、目录填空和不服务于判断的技术长段。不按标题数量、页数、保留词频或是否看多评分。

关键证据缺口、错误事实、重复计价或无法复算，不能靠更强硬或更流畅的文字获得验收。对新候选，关键因果链不足或重要假设既无依据又未分析影响，返回同一研究者补齐；确实无法可靠估值/建模时，说明完整的 `null` 结果可以验收。语义检查由协调器执行，不以新增关键词替代，也不追溯删除已验收报告。

### 产业知识积累

[产业专题](../research/industries/README.md)保存跨公司可复用的竞争机制、证据和未决问题。单公司研究按需参考并核验，不因专题缺失等待、不以专题替代完整报告、不从专题派生公司状态。专题维护沿用现有协作，不另建行业队列或调度；公司 worker 的可复用发现可交给协调器在本轮验收后归并，避免并行覆盖共享专题。

### 长期精选

[长期精选](../selection/principles.md)在有效完整研究之上作横向取舍，依[精选流程](../prompts/selection/long-term-selection.md)维护普通 Markdown 卡片。入选不等于当前买入，研究覆盖池仍是所有 active covered 的确定性投影。精选不改研究状态、质量池或估值，价格和 IRR 不作统一排名；公司报告变化或失效后，旧卡在重新确认前按待复核处理。

### 既有当前稿修订例外

用户在[专项系统迭代](../docs/reviews/2026-09-system-upgrade/README.md)中明确授权，按冻结清单审核并原路径修订已吸收2026中报的当前报告。依[修订规范](../prompts/company/current-report-review.md)提交完整候选，协调器验收后使用专用维护入口同步报告、研究字段和覆盖池。原信息截止、未解决的更晚失效事实及队列保留；其他历史稿不动。此次例外结束后，常规正式报告仍追加且不可变。

2026-09-18 的规范与写作升级不使用上述例外，不修改历史或当前公司报告、研究状态、队列、自选池或模型数据。新规范供后续正常研究使用；文体升级本身不触发重算、重写或旧报告失效。

## 公司研究日志

不越过当前正式报告边界的事件，可以追加：

```text
research/companies/CN/{ticker}/updates/YYYY-MM-DD[-NN].md
```

update 只允许三种影响：

- `reaffirmed`：新事实确认当前报告；
- `monitor`：信息仍在原报告边界内，继续观察；
- `invalidated`：宣告当前报告失效，转 `stale` 并创建完整研究任务。

update 必须引用基础正式报告、事件 ID、事件摘要、分析、结论和来源。它不得修改：

- `value_range` 或正常化利润；
- `return_model` 或 `return_model_note`；
- 核心逻辑或风险排序；
- `covered / ignore`；
- 正式报告指针或信息截止时间。

每次 update 都必须在公司状态行推进 `updated_at`，并写入 `last_update`：日志路径、影响类型、审阅时间、该事件的信息截止点、事件 ID、摘要、来源和基础报告。这个字段是跨系统审计凭据，不会把 update 冒充为新的正式报告，也不会改写正式报告的 `information_cutoff`。

`invalidated` 只说明为什么旧报告已经不能使用；替代结论必须由后续完整正式报告给出。

已有正式报告的公司不得再通过全市场初筛的 `research_now` 路径直接失效。处理公告时必须先比较事件事实时间与当前报告的 `information_cutoff`：

- 事实时间不晚于报告截止点：视为已被当前报告吸收，不改变状态，也不重复排队；
- 事实时间晚于报告截止点、但没有越过报告边界：写 `reaffirmed` 或 `monitor` update；
- 事实时间晚于报告截止点、且足以改变正式报告：写带明确 `information_cutoff` 的 `invalidated` update，由协调器转 `stale` 并创建完整研究任务。

`stale` 的失效时间不得早于当前正式报告截止点，且必须引用实际存在的 `invalidated` update 文件。这样即使公告扫描回补旧窗口，也不能用历史公告推翻更新后的正式报告。

## 触发机制

公告扫描覆盖全部 active 公司，包括 `ignore`。典型触发包括：

- 年报、半年报、一季报和三季报；
- 业绩预告、重大合同、并购、融资、股本和控制权变化；
- 处罚、治理、关联交易和资本配置变化；
- 铜价、产品售价、运价、利率、汇率、产能利用率等经营或行业变量。

证券自身的收盘价、涨跌幅、估值区间穿越不触发研究。仓库不保存 `price_levels`、`price_monitor`、armed/hit/rearm 或每日收盘扫描结果。

公告扫描与完整研究是两条独立链路：扫描从最近一次成功检查点直接推进到当前时间，完成公告发现、裁决、研究日志和排队；独立的研究队列消费者再通过 `research next` 逐家公司完成完整研究。扫描不得顺带消费队列，也不应固定只清理一个很短的历史切片；只有在数据源故障恢复时才临时缩小窗口。

典型流转：

```text
ignore + material_event       -> candidate 或 ignore
covered + fact_in_range       -> reaffirmed / monitor update
covered + report_invalidated  -> invalidated update -> stale + full research
covered + valuation_change    -> stale + full research
covered + return_model_change -> stale + full research
stale + research_complete     -> covered 或 ignore
```

## 行情和网站边界

网站是附带的只读展示，不是仓库的主要产品。它可以现场获取行情，并机械展示：

```text
当前价格 / value_range.low
当前价格 / value_range 中枢
```

若存在 `return_model`，展示层还可以把实时现价作为唯一动态输入，按以下统一公式分别求第五年终值低端和高端对应的 IRR；存在独立 `year_3` 时再单独计算三年结果：

```text
现价 = Σ[D_t / (1 + r)^t] + TV_H / (1 + r)^H
```

五年是主口径，三年只是可选的补充观察，不得共用或机械折算终值。研究仓库只保存 `D_t` 和 `TV_H`，不保存求得的 IRR；现价变化只重算展示结果，不触发研究。无法取得行情或无法求解时显示 `—`。

这些机械派生值不得写回研究状态，不得称为买入信号、关注价、“安全边际充分”或投资授权，也不得生成收益率阈值、概率权重、价格提醒或 armed/hit/rearm 状态。

原模型中的分配或资本行动如果已在原截止之后实施，当前价格可能已与旧现金路径不匹配。本轮审核中经实施公告确认的问题存入 `last_revision.display_issue` 并绑定原报告和模型时点，展示层暂停该模型的现价 IRR，显示现金路径待更新。不得把已支付分红继续视为新买入者未来收入；解决须形成时间和权益口径一致的完整模型。该凭据不修改原截止研究结论，也不是价格触发状态。

## 状态维护

唯一事实源：

- `coverage/cn-a/research_state.jsonl`：证券范围与公司研究状态；
- `coverage/cn-a/research_queue.jsonl`：当前任务；
- `research/companies/CN/{ticker}/reports/`：完整正式报告；
- `research/companies/CN/{ticker}/updates/`：研究日志；
- `research/companies/CN/{ticker}/legacy/`：隔离旧稿；
- `research/watchlist.jsonl`：active covered 的确定性投影；
- `coverage/cn-a/event_scan_state.json`：公告扫描检查点。

共享 JSONL 只由协调器原子写入。worker 只返回最终结构化结果。状态变更后重建自选池并执行 `python -m trading_os validate`。

一次性迁移：

```bash
python -m trading_os state migrate-v3 --at <带时区时间>
```

v3 删除证券价格层、价格运行状态和证券价格型事件条件，保留财报、公司事件及经营变量触发。

## 验收

- active 范围没有遗留 `unseen`；
- 只有 `candidate / stale` 有活动任务；
- current 报告是最新、非空、自足的日期化完整报告；
- 状态和自选池不存在证券价格触发字段；
- update 没有修改正式估值或结论，invalidated 正确创建完整研究任务；
- 每份新正式结果均有非空 `return_model_note`，且 `return_model` 合格或为 `null` 并说明不可可靠建模的原因；模型以五年为主、可选三年终值独立形成，当前价值未被用作未来终值；
- 自选池与 active covered 完全一致；
- 公告扫描覆盖全部 active 公司；
- `python -m trading_os validate` 通过。
