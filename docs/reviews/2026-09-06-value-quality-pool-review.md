# “统计深研公司进度”筛选与实现审查

审查日期：2026-09-06。对象为该任务的 2026-08-31 筛选底稿，以及提交 `75208da9e` 落地的独立价值质量池。正式池信息截止仍为 2026-08-31，共 167 家，其中 A 核心护城河池 48 家、B 质量研究池 119 家。

本次通读名单、方法、筛选脚本、落地模块和测试，对争议成员与遗漏对象进一步核对仓库中的业务、财务和风险材料。这是对筛选判断与实现的 review，没有对全 A 股重新开展一轮研究，也没有重新验证所有公告原件。下文公司意见是基于所引材料的筛选判断，不构成新的正式公司结论。报告是否 covered/stale 不作为质量判断条件。

## 结论

整体方向合理：以商业质量收窄范围，把金融、资源和稀缺基础设施纳入适配口径，区分核心池和待验证池，并与价格及公司研究状态隔离，均值得保留。

但这份名单更适合作为经过初步判断的研究起点，还不能视为已经充分验收的“全市场优质公司全集”。主要问题是核心分层偏宽、同类公司待遇不一致、逐公司理由在正式化时大量丢失，以及全市场遗漏检查缺少可核对的完成记录。

不应先设定一个新的数量目标，也不应为了减少研究量机械删掉某个行业。先修订判断依据，再决定人数。

## 二、筛选流程与规范问题

### P1：正式结果没有保存多数公司的判断依据

实际统计：167 家仅 34 家有 `note`，133 家没有；48 家 A 池中有 38 家没有备注，119 家 B 池中有 95 家没有。合同将 `note` 设为可选，也不允许独立来源字段。

原始 `build_review_pack.py:133` 用手工备注或原状态摘要的第一句当作入选理由；没有正式报告且没有手工备注的 17 家共用“财务质量通过第一轮”的模板。生成的 dossier 主要拼接状态摘要、逻辑与风险，并不等于对每家做了新的独立质量论证。正式化脚本又只保留手工备注，其他理由全部丢掉。

后续 Agent 无法可靠区分“已充分证明”“已读过但存疑”“只是暂时收进来”。这是比人数偏多或代码长度更优先的问题。

建议每家只保存一张简短判断卡：入池理由、现金收益依据、关键反证、分层理由及 1—3 个公开来源。无需建立 evidence ledger、审批链或长篇报告。B 必须写清待验证问题；A 必须写清为什么现存反证没有推翻优势兑现。来源可以独立获取，不绑定公司研究报告或状态。

### P2：全市场边界与完成程度不可复核

底稿合并了 5,552 家状态记录与 5,526 家历史财务快照。26 家没有历史快照指标，不能仅因总体计数是 5,552 就说已完成同等深度的财务筛选。它们未必应入池，新上市历史也可能构成合理排除理由，但需要明确记录处理方式。

基础数据主要为 7 月底历史快照；8 月中报刷新集中在最后入选的 167 家，因此未入选公司同期出现的新事实可能没有进入反向遗漏判断。正式 `universe_count` 还在导入脚本中硬编码为 5552，缺少证券清单来源和该清单日期。

建议保存清单来源、清单日期、数据缺口数量以及本轮重点排除/补查的简短说明。无需把 5,552 家再做一次完整研究，也无需新增一个会与研究状态竞争的全市场状态系统。每轮的成员变化和重要近邻排除理由可在 Git 提交说明中保留。

### P2：商业质量和价格分离在原始过程里并不彻底

临时 `build_screen.py:278` 将 PE 直接计入 `quality_score`，可贡献 +8 至 -5 分；该分数又用于 45 分候选门槛。价格不只影响最后展示，也会影响人工看到哪些公司。另有确定的分支错误：负 PE 会命中 `pe <= 25`，得到 +5 分。临时表中存在 123 家负 PE、三年盈利及其他机械门槛同时通过的记录。该数字说明错误分支不是纯理论场景，但不能推断这些公司最终入选或被遗漏。

现金转换还按可得年度求分子、按全部可得利润求分母，缺失期间没有严格配对；合并现金流与归母利润的混用也不能直接等同于普通股所有者现金。这些指标适合作为发现异常的代理值，不应给出过强精度感。

正式规范已经比临时稿进步：B 的定义移除了“估值待验证”，要求估值不决定质量分层。但 `pool.json` 的传音和海康备注仍保留“要求折价”，与池内不保存折价、溢价的规则不一致。

建议将质量排序完全去价格化，现金口径按同期间配对并标明缺失及少数股东影响；估值留给独立展示。历史临时脚本不必全部产品化，但再次使用前应先纠正这些问题。

## 三、实现评价

### 值得保留

- `pool.json` 唯一事实源，`current.md` 确定性生成，历史交给 Git；这比多个手工名单和日期副本清楚。
- 独立的 status / validate / list / replace，不读写公司研究状态、队列和自选池；提交 `75208da9e` 的文件范围也没有混入共享研究状态。
- 白名单字段、代码去重、日期格式、分层和投影一致性检查，是合适的基本保护。
- 不需要增加经理、复核 Agent、自动审批、复杂评分体系或数据库。

### P2：双文件替换有可复现的半成功状态

`src/trading_os/screening_pool.py:307` 先写 JSON，再写 Markdown。第二次写入失败时，命令报错，但 JSON 已变更，Markdown 留在旧版本。`status` 和 `list` 都先调用完整 validate，随后也会失败。

本次在系统临时目录注入第二次写入失败，复现了“replace 报错、唯一结果源已变、后续 validate 报投影不一致”。此外 `_atomic_write_text` 使用固定临时文件名，没有写锁；多个替换进程可能互相覆盖临时内容或触发删除竞争。

对当前轻量仓库，建议采用唯一临时文件和池级短写锁，并明确 JSON 的提交点。把 Markdown 当作可恢复投影，提供只从已保存 JSON 重建的 render/rebuild 命令。投影损坏不应阻塞读取权威 JSON 的 status/list，独立 validate 继续严格报错。无需为了一个派生 Markdown 引入分布式事务。

### P2：格式验证不能被理解为筛选验收

实测 `CN:999999`、任意非空名称与行业都可以通过解析；`note` 写入“现价100元，低于80元买入”也能通过。当前校验器验证的是结构，不核实证券身份、论据真实性或自由文本中的交易内容。

建议用独立证券清单检查代码、名称和上市范围，不读取研究状态作资格判断。先用少量明确规则拦截显式价格、交易指令等误写，再由执行筛选的同一 Agent 完成语义自查；不承诺正则能够证明内容合规或商业质量。补充缺理由、缺来源、名称代码不符、禁止内容、第二次写入失败及并发写入测试。

`core_moat` 必须在 JSON 中整体排前、禁止空池、`schema_version=1.0` 被接受等属于更低优先级的接口细节。可以在后续顺手修整，不值得先于证据与恢复能力重构。

## 四、是否真正减少了工作量

独立池和研究队列彻底隔离是当前明确的边界，不能在本次 review 中把名单自动接入研究调度。但必须认识到：创建 167 家质量池本身没有把原有数百家研究任务收窄；两套流程仍会各自运行。

若用户后续目标只是获得一个可看的质量名单，当前隔离设计合适。若目标是减少持续深研资源消耗，则需要另行明确调整研究范围与维护政策；不能一边声明完全隔离，一边暗中用池成员过滤、失效或删除研究任务。本次不执行此类改动。

筛选层自身还应补上轻量维护约定：何时复看成员，何时做行业反向遗漏检查，新上市历史不足如何处理，成员降级或退出的事实条件是什么。优先由竞争、治理、资本配置、所有者现金等新事实驱动，不因现价或短期利润涨跌机械调整，也不为本池复制一套公告扫描与研究队列。

## 五、建议处理顺序与验证
