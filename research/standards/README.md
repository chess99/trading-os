# 现行研究展示标准

本层只决定最新财报周期的结构化模型能否进入研究台，不改变公司估值、周期排期、质量池或报告正文。价值含义仍唯一引用[主提示词的价值定义](../../prompts/company/standard-deep-research.md#价值定义)。

## 展示规则

最新周期模型默认取动态重点跟踪池范围，只展示 `basis_report_path` 所指向、按现行兼容标准完成的研究。研究完成但暂无法估值，或周期结论为 `ignore`，仍可以是合格结果。范围、结论、标准版本和资料时点分别处理。

研报库按公司直接打开最新财报周期，并可切换其他周期。每个周期只保留最后一次完整研究；非最新周期统一作为历史研究阅读，不加载现价、不附最新摘要、不算现价 IRR。最新周期没有兼容标准结果时不回退早期模型。

## 唯一配置与状态

- `registry.json`：正式发布的研究标准、冻结的规范提交、价值语义标识、默认范围及显式兼容关系。
- `coverage/cn-a/research_state.jsonl`：最近完成周期及其 `standard_id`、`spec_revision`、`accepted_at`。这三个字段随 `research complete` 一次写入，不另建报告级登记文件。
- 报告正文、估值和模型继续只存在正式周期报告及研究状态中，不保存摘要、哈希、撤销记录或第二份估值。
- 展示目录、进度、JSON/CSV 导出均由这些源数据确定性生成到 `dashboard/public/data/`，禁止手改。旧估值在生成目录时就被置空，不只在页面隐藏。

`research complete` 是协调器完成商业、原证、财务、模型和正文验收后的唯一正式写入口。未通过的候选稿直接丢弃；通过后自动使用当时已发布的 active standard 给状态盖章。同周期重写再次走完整验收并覆盖文件、状态和标准信息，Git 保留旧修订。

标准信息只描述这份最新周期研究执行时采用的规范，不提高资料截止，也不证明公司经营截至今天没有变化。

## 标准升级

新标准默认从下一财报周期采用，不为规范变化自动创建中途任务。若用户明确要求立即重做某一既有周期，使用 `research enqueue-rewrite`，完整覆盖该周期并按新标准重新完成。

“现行”是显式发布状态，不是最近一次提示词提交。草案不能设为现行。每次发布说明变化、影响范围、是否兼容及理由：

- `patch`：表达或工具改进，不改变必要研究要求和价值含义，通常兼容；
- `minor`：研究要求的兼容改进，明确列出可以继续使用的旧标准 ID；
- `major`：必要研究要求或价值语义发生实质不兼容变化，旧模型退出默认展示，等待下一周期研究或用户明确要求的同周期重写。

不通过数字版本大小猜兼容性，也不进行传递兼容推断。兼容版本必须在现行标准的 `compatible_with` 中逐项列明并附理由；不同价值语义不能直接声明兼容。历史标准声明保留，以便解释旧状态。

## 检验与发布

```bash
python -m trading_os validate
node dashboard/scripts/report-standards.mjs validate
cd dashboard
npm test
npx tsc --noEmit
npm run lint
```

`report-standards.mjs` 现在只校验 registry 与状态中的标准字段，不再提供 `inspect / accept / revoke`。工程检查只证明配置、状态和展示关系正常，不重新认证公司的商业预测。网页仍是构建时快照；提交代码不是部署。
