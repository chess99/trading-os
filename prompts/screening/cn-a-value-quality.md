# 全 A 股价值质量池筛选规范

## 目标

以长期普通股所有者的视角，在全 A 股中维护一个足够窄、但不过度漏掉优质公司的当前池。筛选关注商业模式、护城河、所有者现金收益和治理质量；它不是买入名单，也不替代单公司完整研究。

本层与单公司研究层完全隔离：

- 唯一正式结果是 `screening/cn-a/value-quality/pool.json`；
- 不修改 `coverage/cn-a/research_state.jsonl`、`coverage/cn-a/research_queue.jsonl`、`research/watchlist.jsonl`、公司报告或研究日志；
- 不创建、领取或完成单公司研究任务；
- 单公司研究流程也不读取本池来改变状态、队列、报告结论或自选池；
- 可以把公司报告当作普通参考材料，但不能把 `covered / stale / candidate / ignore` 当作入池条件，也必须允许在没有报告时独立筛选。

## 两层结果

- `core_moat`：商业模式和竞争优势已经足以进入核心长期研究范围。估值昂贵不取消资格。
- `quality_research`：存在真实优势，值得继续完整验证；但护城河强度、行业变化、治理、资本强度或所有者现金转换至少有一项尚未得到充分证明。

不得为了满足数量目标而增删公司。池子可以扩大或缩小，但每次都必须是全量快照。

## 判断框架

逐家公司回答以下问题：

1. 客户为什么持续选择它，竞争者为什么难以复制？
2. 优势主要来自品牌与渠道、切换成本、网络效应、成本曲线、牌照与标准、数据与研发体系，还是长寿命稀缺资产？
3. 优势是否能穿越至少一个行业周期，还是只来自商品价格、补贴、产能紧缺、项目验收或会计口径？
4. 增长能否最终转化为普通股所有者现金，还是长期依赖资本开支、并购、再融资或营运资本占用？
5. 高 ROE 是否由真实经营优势产生，还是主要由杠杆、低权益基数、一次性收益或周期高点造成？
6. 控股股东、关联交易、少数股东、股权激励、稀释和资本配置是否会截留经营价值？
7. 如果行业不再增长，公司是否仍能依靠份额、成本、复购、服务或定价权获得高于资本成本的回报？

金融、资源、公用事业和重资产基础设施使用行业适配口径。不得因为它们不符合制造业自由现金流模型而机械剔除，也不得因为低 PB、高股息或资源价格上涨而自动入选。

## 常见否决项

- 利润主要由商品价格高点决定，且没有可验证的成本曲线或资源禀赋优势；
- 项目制、单一客户或爆款产品制造了短期高增长，但缺少复购、切换成本或议价权；
- 低毛利规模扩张持续消耗营运资本，收入增长没有转成每股现金；
- 普通牌照、地域保护或融资杠杆被误当成永久护城河；
- 上市时间过短，治理和资本配置尚未经历公开市场检验；
- 需求结构性收缩、长期低 ROIC，又缺乏退出、提价或再投资能力；
- 关联交易、少数股东分流、持续稀释或糟糕资本配置足以抵消经营优势。

## 筛选流程

1. **确认全市场边界。** 使用最新可得的完整证券清单，记录 `universe_count` 和信息截止日。
2. **批量压缩事实。** 可用脚本整理多年收入、利润、ROE、现金转换、资本强度、杠杆、审计、行业和业务描述。机械指标只负责排序和发现异常。
3. **人工判断商业质量。** 按上述框架逐项判断，不允许单一财务分数决定入池。
4. **做反向遗漏检查。** 专门复核因资本开支、短期现金流、周期位置或行业口径而被机械模型压低的品牌、平台、低成本龙头与稀缺资产。
5. **做反向误入检查。** 专门复核商品高点、客户集中、并购并表、爆款和低毛利规模增长带来的假质量。
6. **全量替换并验证。** 生成完整 JSON 后运行 `quality-pool replace`，再运行独立校验。不得增量手改 `current.md`。

允许自由获取公开信息，也允许使用仓库外临时底稿。底稿、行情快照、抓取缓存和机械中间表不进入正式池。

## 商业质量与价格分离

池子只回答“这家公司是否值得长期研究”，不回答“今天是否值得买”。以下内容不得写入池中：

- 当前价格、市值、PE、PB、折价或溢价；
- 价值区间、IRR、收益率门槛、买入价或价格触发；
- 仓位、交易建议或组合动作；
- 单公司研究状态、任务 ID、报告路径、报告截止日或 `return_model`。

估值信息可以在临时分析中帮助检查市场预期，但不能决定商业质量分层，也不能固化在当前池。

## 正式结果合同

使用以下命令以全量快照替换当前池：

```bash
python -m trading_os quality-pool replace --input <pool.json>
python -m trading_os quality-pool validate
python -m trading_os quality-pool status
python -m trading_os quality-pool list --tier core_moat
```

输入是一个 JSON 对象：

```json
{
  "schema_version": 1,
  "as_of": "2026-08-31",
  "universe_count": 5552,
  "methodology": "prompts/screening/cn-a-value-quality.md",
  "philosophy": "以长期普通股所有者视角优先选择可理解、可持续产生现金、具备结构性竞争优势且治理可接受的公司；商业质量与价格分开判断。",
  "companies": [
    {
      "symbol": "CN:600519",
      "name": "贵州茅台",
      "industry": "白酒Ⅱ",
      "tier": "core_moat",
      "group": "consumer_brand_network",
      "note": "可选的简短筛选备注"
    }
  ]
}
```

`tier` 只允许 `core_moat / quality_research`。`group` 只允许：

- `consumer_brand_network`
- `healthcare_platform`
- `technology_industrial`
- `infrastructure_finance_resource`

`note` 可选，只记录对入池或分层真正有帮助、且不含动态价格和单公司研究状态的判断。公司代码必须唯一，A 池整体排在 B 池之前。

`pool.json` 是唯一结果源，`current.md` 是由它确定性生成的可读投影，禁止手改。正常运行只维护当前版本；需要查看历史时使用 Git。

## 交付检查

- 全市场边界和 `as_of` 明确；
- 代码唯一、名称与行业可识别；
- 每家公司只属于一个 tier 和一个 group；
- A/B 分层符合定义，没有为了数量凑池；
- 完成反向遗漏和反向误入检查；
- 池内没有行情、估值、交易动作或单公司研究耦合字段；
- `quality-pool validate` 通过；
- 单公司状态、队列、自选池和报告没有因本次筛选发生变化。
