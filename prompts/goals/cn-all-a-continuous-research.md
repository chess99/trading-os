# 全 A 股持续研究 Goal

> 在新的 Codex 任务中引用本文件，并补充本次参数。执行细节以根 `AGENTS.md` 和 `playbooks/simple-research.md` 为准。

请创建并持续执行一个全 A 股研究 Goal。目标不是反复从头研究全部公司，而是先建立一次全市场基线，随后维护公司当前状态、自选池、每日收盘价格触发和财报/重大事件变化。

## 参数

- `mode`：`auto`（默认）、`baseline` 或 `incremental`。
- `run_id`：未指定时按启动日期和用途生成稳定 ID。
- `information_cutoff`：本轮可以使用的信息截止时间；未指定时使用启动时的带时区时间。
- `universe_ref`：未指定时使用仓库内可验证的最新普通 A 股范围。
- `company_parallelism`：单公司任务并发配置；未指定时按环境资源决定，通常同时运行 3–6 家。

`auto` 必须先读取现有状态：只有尚未建立有效基线时才执行 `baseline`；已有基线时直接执行 `incremental`。不得因为启动了新任务就重新跑完整初筛。

## 唯一流程

```text
一次性全市场批量判断
  ├─ ignore：记录理由和重新观察条件，结束
  ├─ watch：进入观察状态，等待价格或事件
  └─ research_now：派一个单公司 Agent
                         ↓
                 自适应完成单公司研究
                         ↓
              ignore / watch / researched
                         ↓
                    派生自选池
                         ↓
        每日收盘价格扫描 + 财报/重大事件变化筛选
```

## 主 Agent 的职责

主 Agent 是研究资源的判断者，不是任务转发器。它亲自分批浏览全市场压缩材料，用一致口径判断每家公司是：

- `ignore`：当前明显不值得继续投入研究资源，只保留简短理由；有明确的公司特定重看条件时再补充；
- `watch`：值得保留线索，但应等待价格、财报、公告或其他明确条件；
- `research_now`：当前机会或关键变化值得单独研究。

判断时关注公司如何赚钱、竞争优势是否可信、利润能否转化为股东现金流、资产负债表与治理风险、当前估值大致隐含什么，以及什么事实会改变结论。程序只负责准备事实、证券身份和新增事件，不能替主 Agent 决定路由。

不要设置正式研究公司的数量目标或比例。真正值得研究的公司可能只是数百家，也会随市场变化；数量必须来自主 Agent 的逐家公司专业判断。不能为了填满队列而派任务，也不能机械地按行业、市值、盈利正负或既有标签决定。明显不值得研究的公司在批量判断阶段结束，不创建单公司 Agent 和冗长报告。

批量判断只更新全市场当前状态，不为每家公司生成 Markdown 报告。不得用固定年化收益率门槛决定一家公司能否继续研究。

主 Agent 可分多批完成基线，但必须覆盖冻结范围。每个 baseline 批次只能包含当前仍为 `unseen` 且尚未做过 baseline 判断的公司；混入任意已判断公司时必须整批失败，不得部分写入。基线完成后只处理新增公司和发生变化的公司，已有公司通过 event 增量判断更新。

## 单公司 Agent 的规则

只有 `research_now` 可以派发。不同公司相互独立，允许按 `company_parallelism` 并行；同一家公司始终只有一个 Agent，从资料查找到结论写作端到端完成。

单公司 Agent 先快速浏览，再按发现自适应展开：

- 很快确认没有研究价值时，及时停止；`discard` 只给出非空的简短定性结论，关键逻辑、来源和公司特定重看条件均可省略；
- 基本面没有实质变化时，只做简版更新；
- 发现真实机会、重要变化或需要推演的估值问题时，再写完整报告。

不写死研究时长，不预先分配研究等级，不因流程形式继续消耗时间。研究深度由同一个 Agent 根据公司复杂度、信息质量和潜在价值决定。

任务开始后，单公司 Agent 自行完成工作并只返回一次最终结构化结果。不要设置第二研究者、复核人、批准节点或 Agent 之间的中间交流。协调器只控制并发、接收最终结果并串行写入共享状态；单公司 Agent 不直接修改共享文件。

## 单公司结果

正式研究只保留一份当前报告：`research/companies/CN/{ticker}/current.md`。内容以支持后续观察为准，重点包括：

1. 一句话结论和关键逻辑；
2. 最重要的正面变量与风险；
3. 合理价值区间和主要假设；
4. 值得重新关注的买入触发价；
5. 会强化、削弱或推翻判断的后续财报与事件条件；
6. 信息截止时间和可直接打开的来源 URL。

若快速判断后决定放弃，可以只输出简短结论，不强行制作完整报告。不得要求仓位建议、自动交易动作或伪精确的收益率结论。价格触发代表需要重新关注，不代表自动买入。本流程在复看和排序清单处结束，投资决定交给用户，不再追加跨公司审批步骤。

完成后把公司更新为 `ignore`、`watch` 或 `researched`，并同步必要的理由、触发条件和报告位置。

## 当前状态与自选池

使用以下当前事实源：

- `coverage/cn-a/research_state.jsonl`：全市场公司当前状态；
- `research/watchlist.jsonl`：从当前状态派生的自选池；
- `research/companies/CN/{ticker}/current.md`：正式研究的当前报告。

状态只使用 `unseen / ignore / watch / researched`。持仓属于用户账户信息，不混入研究状态；`research_now` 只是派发决定，不保存在长期状态中。

自选池通常纳入带有效触发条件的 `watch` 和 `researched` 公司，排除 `ignore`。初筛形成的 `watch` 至少保留证券代码、名称、观察理由和一个价格或事件触发条件；完成正式研究后，再补齐关键逻辑、关键风险、合理价值区间、买入触发价、事件条件、最近研究日期和价格日期。自选池必须能从公司当前状态重新生成，不能维护两套互相冲突的判断。

## 每日收盘价格扫描

价格监控只在每个交易日收盘后执行一次：

1. 获取并记录当日收盘价与日期；
2. 扫描自选池的有效买入触发价；
3. 只对从未触发变为触发的公司提示，同一状态不重复提示；价格离开触发区间后才能再次待命；
4. 主 Agent 对当天触发公司做简短复看，检查最新信息和原逻辑是否仍有效；
5. 按吸引力、确定性与变化程度排序，给出当天值得人工关注的清单。

扫描输入必须覆盖当前所有带价格监控的 `watch` 和 `researched` 公司；缺少任意一家收盘价时整批报错且不更新触发状态。扫描器只返回价格命中，不创建研究任务。只有主 Agent 复看发现基本面或信息发生实质变化时，才标记 `research_now`。

## 财报与重大事件

定期报告、业绩预告、重大合同、监管处罚、控制权或资本结构变化等新增事件，先对全市场做批量变化筛选，自选池内外公司都必须有重新进入判断的机会。

- 没有实质变化：保持原状态，不写入本次状态变更，也不派 Agent；需要时只在本轮汇总中记一句；
- 有观察价值但证据不足：进入或保留 `watch`，写清下一触发条件；
- 明显改变商业质量、现金流、风险或估值：标记 `research_now`，派一个单公司 Agent 更新。

池外公司可以因重大变化重新进入自选池；池内公司也可以因逻辑证伪转为 `ignore`。

`event` 输入只包含需要改变当前状态或标记为 `research_now` 的公司。`ignore / watch / research_now` 与基线含义一致，不得把 `ignore` 当成“无变化”的占位符。

## 启动与恢复

每次启动或恢复时：

1. 完整读取根 `AGENTS.md`、`playbooks/simple-research.md`、本 Goal、Git 状态和三个当前事实源。
2. 保留用户及其他并行工作的修改，不切分支，除非用户明确要求。
3. 若基线存在，先从状态中确定新增公司、未完成任务、当日价格和新增事件，禁止重新冻结并重跑已有公司。
4. 若单公司任务中断，只恢复该公司的任务；不要重做已经完成的其他公司。
5. 写共享状态前校验证券代码唯一、状态合法、报告路径存在、自选池可重建、触发条件可执行。
6. 每完成一个完整迭代，验证并只提交本轮自己修改的文件。

## 旧机制迁移与清理

迁移时先提炼仍有用的最新结论，再生成新的公司当前状态、当前报告和自选池。失败、重复、已被新结论替代或仅为流程留痕的资产不进入新机制。

本阶段只清理当前工作树：删除当前版本中不再使用的旧流程文件、重复报告和本地来源副本。不要重写 Git 历史，不要强推远端；删除内容仍可从历史提交恢复。等新机制稳定后，历史压缩和远端重写必须作为单独任务执行。

## 每轮验收

基线轮至少确认：

- 冻结范围内每家公司都有一个当前状态；
- baseline 批次只处理 `unseen`，不会覆盖已有判断或留下半批更新；
- 只有 `research_now` 创建了单公司任务；
- 每个单公司任务只有一个 Agent 和一个最终结果；
- 自选池能由当前状态完整重建。

增量轮至少确认：

- 只处理新增公司、真实新增事件和本次收盘价；
- 收盘价覆盖全部价格监控标的；价格提示已去重、可在离开触发区间后重新待命，且扫描本身没有创建研究任务；
- 池外公司的重大事件已进入批量变化判断；
- 没有因普通公告或无实质变化的财报滥发单公司任务；
- 状态、当前报告、自选池和来源 URL 相互一致。

最终向用户报告本轮模式、信息截止时间、覆盖或变化数量、三个判断的数量、实际派发公司、完成结果、自选池变化、当日价格触发、重大事件变化、阻塞项、验证和提交。不要汇报无意义的流程层级或 Agent 间往返记录。
