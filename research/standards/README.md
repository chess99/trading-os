# 现行研究展示标准

本层决定哪些最新财报周期模型可以进入研究台，不改变公司估值、周期排期、质量池或报告正文。价值含义仍唯一引用[主提示词的价值定义](../../prompts/company/standard-deep-research.md#价值定义)。

## 三个入口

最新周期模型默认取动态重点跟踪池范围，只展示其 `basis_report_path` 所指向、通过现行兼容标准验收的报告。研究完成但暂无法估值、或周期结论为 `ignore`，仍可以是合格结果。范围不等于质量认证，`covered` 也不等于通过现行标准。

跟踪进度展示重点池全体，包括尚无周期报告、目标周期待研究、验收待复核和已完成但暂不能估值。池成员和 A/B 分层由当前筛选结果动态增删。

研报库按公司直接打开最新财报周期，并可切换其他周期。每个周期只保留最后一次完整研究；没有验收元数据的报告显示“历史标准未确认”。非最新周期不加载现价、不附最新摘要、不算现价IRR。最新周期没有合格验收时不回退早期模型。

## 唯一配置与绑定

- `registry.json`：正式发布的现行标准、冻结的规范提交、价值语义标识、默认范围及显式兼容关系。
- `acceptances/{代码}/{财报周期}.json`：既有协调器实质验收的登记，绑定具体周期报告、正文摘要、结构化研究摘要、原资料截止、规范版本、验收时间、结论状态和说明。同周期正文重写后原登记自然失效，须重新验收覆盖。
- 估值和模型继续只存在原研究状态及正式正文中；验收记录不保存第二份估值。内容摘要只识别登记对应的版本，不构成商业质量证明、签名权限体系或新增审批角色。
- 当前展示目录、进度、JSON/CSV导出均由现有源数据确定性生成到 `dashboard/public/data/`，禁止手改。旧估值在生成目录时就被置空，不只在页面隐藏。

登记不提高资料截止，也不证明公司经营截至登记日未变化。财报周期、资料截止、是否符合标准、是否存在可用估值及模型与当前价格的关系分别展示。

## 后续研究如何登记

沿用同一协调器。实质验收及 `research complete` 入库后登记，随正式输出一并提交；不另开一轮研究角色。缺少登记的新报告只会等待展示，不会自动认证。先检查当前文件与结构化快照：

```bash
node dashboard/scripts/report-standards.mjs inspect --symbol CN:300750
```

完成原规范要求的商业、原证、财务、模型及正文验收后，用刚检查的两个摘要登记。下列尖括号必须替换，不能直接提交示例：

```bash
node dashboard/scripts/report-standards.mjs accept \
  --symbol CN:300750 --standard owner-value-1.0 \
  --report-sha <inspect中的report_sha256> \
  --research-sha <inspect中的research_sha256> \
  --source-revision <实际读取来源的完整Git提交> \
  --reviewer <本次协调验收者> --confirm-review \
  --note '<本报告具体的验收依据、发现和剩余限制>'
node dashboard/scripts/report-standards.mjs validate
cd dashboard && npm run data
```

登记命令有逐文件锁和原文/结构化结果/既有登记的并发比对；登记已存在时，替换还须 `--expected-receipt <inspect返回的receipt_sha256>`，且实际完成新的复核。原报告或结构化结果变化会使旧登记不再适用，不自动重签。跨机器提交仍须核对Git基线和冲突，锁不代替Git并发检查。

发现验收缺陷可用 `revoke` 代替 `accept`，同时传入公司、刚核对的两项摘要、`--expected-receipt`、验收者、说明和确认；撤销不改正文及估值。涉及经济判断改变时，仍需正常研究更新，不拿撤销登记代替事实层修正。

### 标准升级

新标准默认从下一财报周期采用，不为标准变化自动创建中途任务。若用户明确要求立即重做某一既有周期，使用 `research enqueue-rewrite`，完整覆盖该周期并按新标准重新验收。

## 以后怎样升级

“现行”是显式发布状态，不是最近一次提示词提交。草案不能设为现行。每次发布说明变化、影响范围、是否兼容及理由：

- `patch`：表达或工具改进，不改变必要研究要求和价值含义，通常兼容。
- `minor`：研究要求的兼容改进；明确列出可以继续使用的旧标准ID，不要求改写旧标签。
- `major`：必要研究要求或价值语义发生实质不兼容变化，受影响的旧稿退出默认展示，逐份重研/实质复核后登记。语义不同的价值禁止直接声明兼容。

不通过数字版本大小猜兼容性，也不进行传递兼容推断。兼容版本必须在现行标准的 `compatible_with` 中逐项列明并附理由。历史标准声明保留，不能删除后使旧验收无法解释。季度数据更新通常只改变个别报告，不改变全库标准。

变更影响有限时，仅撤销/更新相关报告。不能因为文风调整或换模型供应商就把全部公司清零；也不能只改标签或给旧稿补几段文字就宣称完成重大升级。兼容性由经济含义与研究要求决定，不以估值高低决定。


`research-display-checks.yml`在相关变更时执行Python回归、状态校验、目录/接口测试、构建和浏览器隔离测试。通过这些工程检查只证明实现与数据绑定正常，不重新认证公司的商业预测。网页仍是构建时快照；提交代码不是部署。实际站点须在正常部署环境重新构建并发布，不能只清浏览器缓存。
